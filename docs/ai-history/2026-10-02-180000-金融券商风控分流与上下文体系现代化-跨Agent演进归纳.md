## 为什么值得保留

2026-07-31 至 2026-10-02 期间，项目经历了业务分流安全策略加固与上下文治理体系现代化的双重重要转折：
1. **金融证券风控与 IP 纯净度诉求**：美股券商（Firstrade、Charles Schwab 嘉信理财）对登录 IP 变动和信誉极其敏感，频繁跳节点或使用公共高流量赠送节点易触发风控冻结。此阶段确立了将海外核心金融交易全量锁定至 `静态住宅` 策略组的重大决策。
2. **国内金融与东财 DNS 本地化**：东方财富等国内金融行情软件需保障超低延迟与国内 CDN 精准调度。若误走代理或国外 DoH 会导致行情刷新异常甚至账号风控。此阶段通过补充直连规则与系统 DNS 映射（`server:system` 及 `dhcp://system`），彻底将国内金融流量收口至本地直连。
3. **上下文体系全面适配 D-004 规范**：废除了带来状态竞争的双真相、运行期 handoff 文档与隐式候选队列，将全套治理无损收敛至单一法定真相（architecture.md）与 README Testing 规范。

这些决策背景与分流动机未来无法单从配置文件逆向推导，必须作为历史演进凭证永久保留。

## 目标与顾虑

### 用户核心目标
- 保护海外重要资产与美股券商账户，杜绝因代理出口 IP 频繁漂移或节点风控引起的账户锁定。
- 保证国内金融与证券交易（如东方财富）的绝对稳定性与低延迟，避免国外 DNS 污染。
- 扩大 AI 平台的精准捕获范围（引入 Grok、Muse，加固 Claude 规则），统一导向最高优先级的 `静态住宅`。
- 将多 Agent 协作上下文对齐最新平台规范，杜绝陈旧交接文件与孤立测试文档。

### 核心顾虑
- 担心国内金融服务误走国外代理或被国外 DNS 污染导致行情断流或违规。
- 担心多 Agent 并行协作时再次出现竞争性状态文档（如过期 HANDOFF）。
